# Figma Code Connect — team setup & usage

Code Connect maps our Figma components to the real `@semio/ui` React code, so that
in Figma **Dev Mode** (and any AI tool backed by the Figma MCP server) selecting a
component shows the true `@semio/ui` snippet instead of autogenerated markup.

The bindings live in `packages/ui/src/**/*.figma.tsx` (one `figma.connect(...)` per
component), configured by [`figma.config.json`](../figma.config.json) which points
them at the published **Semio UI Library** file. They are **not** part of the
shipped npm package (not exported from `index.tsx`, not in `files`) and publishing
them needs **no version bump / release** — they're Figma-file metadata.

## Requirements (verified against Figma docs)

- **Plan:** Organization **or** Enterprise. Code Connect is *not* Enterprise-only —
  there is no Organization/Enterprise feature split for it.
- **Seat:** each person who needs to *see or publish* the snippets needs a **Dev or
  Full seat**. This is the real "team-wide" gate — a View/Collab seat can't open Dev
  Mode, so it can't see Code Connect. It is a per-seat requirement, not a plan tier.
- **Library:** the Semio UI Library file must have its components published (done via
  Assets → Publish).

Refs: [Code Connect (Help Center)](https://help.figma.com/hc/en-us/articles/23920389749655-Code-Connect),
[Code Connect (Developer Docs)](https://developers.figma.com/docs/code-connect/).

## Using it (developers)

1. Have a Dev/Full seat and enable the Semio UI Library in your file
   (Assets → Libraries → **Semio UI Library**).
2. Open the design file in **Dev Mode** and select a connected component
   (Button, TextField, Modal, Card, …).
3. The inspect panel shows the `@semio/ui` code snippet and prop mapping. Copy it,
   or let an MCP-backed AI tool read it — that's the biggest payoff: codegen emits
   real `@semio/ui` usage instead of guessed markup.

## Publishing (automated)

CI publishes on every merge to `staging`/`main` — see the `figma-code-connect` job
in [`.github/workflows/ci-cd.yml`](../../../.github/workflows/ci-cd.yml). It always
validates (`connect:parse` + `parity:figma`) and publishes only on push when the
`FIGMA_ACCESS_TOKEN` secret is present. So the bindings stay in sync team-wide with
no manual step; a local publish is only a fallback.

### One-time setup (manual — repo admin)

1. **Create a Figma access token** (ideally on a shared/service account, not a
   personal one, so publishing isn't tied to one person): Figma → Settings →
   Security → *Personal access tokens*. Set scopes:
   - **Code Connect: Write**
   - **File content: Read**
2. **Add it as a GitHub Actions secret** named `FIGMA_ACCESS_TOKEN`
   (repo → Settings → Secrets and variables → Actions), or:
   `gh secret set FIGMA_ACCESS_TOKEN --repo semio-ai/semio_studio`.

### Manual publish (fallback)

```bash
cd packages/ui
FIGMA_ACCESS_TOKEN=<token> npm run connect:publish     # or: figma connect publish --token <token>
# preview without writing:
FIGMA_ACCESS_TOKEN=<token> figma connect publish --dry-run
```

## Local validation (no token needed)

```bash
cd packages/ui
npm run connect:parse    # parses every *.figma.tsx — fails on malformed bindings
npm run parity:figma     # Figma-contract snapshot ↔ live code drift guard
```

`parity:figma` compares each `figma/*-contract.json` snapshot against the live code
(subset conformance + code-consistency, both directions). Keep the snapshots fresh
from the file when the Figma components change — see
[`figma-design-system-mapping.md`](./figma-design-system-mapping.md).
