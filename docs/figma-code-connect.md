# Figma Code Connect — team setup & usage

Code Connect maps our Figma components to the real `@semio/ui` React code, so that
in Figma **Dev Mode** (and any AI tool backed by the Figma MCP server) selecting a
component shows the true `@semio/ui` snippet instead of autogenerated markup.

The bindings live in `packages/ui/src/**/*.figma.tsx` (one `figma.connect(...)` per
component), configured by [`figma.config.json`](../figma.config.json) which points
them at the published **Semio UI Library** file. They are **not** part of the
shipped npm package (not exported from `index.tsx`, not in `files`) and publishing
them needs **no version bump / release** — they're Figma-file metadata.

## Plan status (important)

> **We are on the Professional plan, where custom Code Connect mappings are NOT
> supported.** Code Connect (publishing mappings + showing `@semio/ui` snippets in
> Dev Mode) is an **Organization/Enterprise-only** feature — the `code_connect:write`
> token scope doesn't even exist on Professional, so `figma connect publish` can't
> run. This is a plan limit, not a seat/role/config issue.
>
> **The work is not wasted:** the bindings are validated in CI and stay
> publish-ready for the day the org moves to Organization/Enterprise. Until then,
> use the plan-independent bridges below.

## Requirements for full Code Connect (Organization/Enterprise only)

- **Plan:** Organization or Enterprise (Professional does not include Code Connect).
- **Seat:** a **Dev or Full seat** to publish/see snippets in Dev Mode.
- **Token scope:** `code_connect:write` + `file_content:read` (only offered to
  org members on the above plans).
- **Library:** components published (done via Assets → Publish).

Refs: [Code Connect (Help Center)](https://help.figma.com/hc/en-us/articles/23920389749655-Code-Connect),
[Code Connect (Developer Docs)](https://developers.figma.com/docs/code-connect/),
[Use code snippets in Dev Mode](https://help.figma.com/hc/en-us/articles/15023202277399-Use-code-snippets-in-Dev-Mode).

## What works on Professional today (use these)

- **Consume the published library** — enable *Semio UI Library* in a file
  (Assets → Libraries) and drag in components / use its variables + styles.
  Plan-independent; this is the main team win.
- **Storybook `design` links** — every component story links to its exact Figma
  node via `@storybook/addon-designs` ([`figma-links.ts`](../../../apps/docs/stories/figma-links.ts)).
  Works for anyone with view access, no Dev Mode needed — the "which code ↔ which
  Figma component" bridge that stands in for Code Connect on Professional.
- **Dev Mode standard inspect** — with a Dev/Full seat, devs get measurements,
  variables, and autogenerated CSS/code (just not the custom `@semio/ui` snippets).
- **Local `connect:parse` + `parity:figma`** — validate the bindings and guard
  Figma↔code drift (see below); runs in CI regardless of plan.

## Using it (developers, once on Organization/Enterprise)

1. Have a Dev/Full seat and enable the Semio UI Library in your file
   (Assets → Libraries → **Semio UI Library**).
2. Open the design file in **Dev Mode** and select a connected component
   (Button, TextField, Modal, Card, …).
3. The inspect panel shows the `@semio/ui` code snippet and prop mapping. Copy it,
   or let an MCP-backed AI tool read it — codegen emits real `@semio/ui` usage
   instead of guessed markup.

## Publishing (automated — dormant on Professional)

The `figma-code-connect` job in
[`.github/workflows/ci-cd.yml`](../../../.github/workflows/ci-cd.yml) always
validates (`connect:parse` + `parity:figma`) on every run, and publishes on push to
`staging`/`main` **only when the `FIGMA_ACCESS_TOKEN` secret is present**. On
Professional that secret can't be created (no `code_connect:write` scope), so the
publish step self-skips and the job effectively just validates. Nothing fails; the
publish path activates automatically if the org upgrades and the secret is added.

### One-time setup (only after an Organization/Enterprise upgrade)

1. **Create a Figma access token** (ideally on a shared/service account, not a
   personal one, so publishing isn't tied to one person): file browser → account
   menu (top-left) → **Settings → Security tab** → *Personal access tokens* →
   Generate new token. Set scopes:
   - **Code Connect: Write** (`code_connect:write`)
   - **File content: Read** (`file_content:read`)

   > **No "Code Connect" scope group in the list?** `code_connect:write` only
   > surfaces when *all* of these hold for the token's account:
   > 1. **Org member, not guest** (guests can view Code Connect but not publish);
   > 2. a **Dev or Full seat** assigned — this is separate from the team *role*
   >    (you can be a team Admin on a Collab/View seat); manage it in the org
   >    **admin dashboard**;
   > 3. the token is generated in the **organization** account context, not a
   >    personal/draft space.
   >
   > Best fix for CI: a **service/bot account that's an org member with a Dev/Full
   > seat** holds the token, so publishing never depends on one person's seat. Do
   > **not** substitute `file_dev_resources:write` — publish needs
   > `code_connect:write` or it 403s. If all three hold and it's still missing,
   > it's usually a plan/seat propagation lag → Figma support.
2. **Add it as a GitHub Actions secret** named `FIGMA_ACCESS_TOKEN`
   (repo → Settings → Secrets and variables → Actions), or:
   `gh secret set FIGMA_ACCESS_TOKEN --repo semio-ai/semio_studio`.

### Manual publish (fallback)

```bash
cd packages/ui
FIGMA_ACCESS_TOKEN=<token> npm run connect:publish     # or: figma connect publish --token <token>
# preview without writing:
FIGMA_ACCESS_TOKEN=<token> figma connect publish --dry-run
```

## Local validation (no token needed)

```bash
cd packages/ui
npm run connect:parse    # parses every *.figma.tsx — fails on malformed bindings
npm run parity:figma     # Figma-contract snapshot ↔ live code drift guard
```

`parity:figma` compares each `figma/*-contract.json` snapshot against the live code
(subset conformance + code-consistency, both directions). Keep the snapshots fresh
from the file when the Figma components change — see
[`figma-design-system-mapping.md`](./figma-design-system-mapping.md).
